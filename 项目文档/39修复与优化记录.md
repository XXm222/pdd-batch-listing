## 一、店铺身份核对误报（截图：后台店铺名称已匹配，但未读取到完整登录账号）

**现象**：店铺名称已匹配，但弹窗报「未读取到完整登录账号，无法确认所选子账号」，核对步骤显示 0.0 秒未完成。

**根因**（真机读 header 取证）：
1. 后台把子账号渲染成 `主账号:子账号(真实姓名)`，行尾带真实姓名，原文比较永远不等于保存的 `主账号:子账号`；
2. 更关键的是——该店**主账号名 ≠ 店铺名**，旧逻辑要求"主账号名必须单独占一行"作佐证，所以身份列表恒为空。历史测试都用"主账号名 == 店铺名"的造型，从未暴露。

**改动**：
- `electron/platforms/pdd-identity.ts`：剥离行尾 `(真实姓名)`（支持多层）；`completePddIdentities(names, shop?)` 增加店铺参数；佐证条件从"主账号名单独成行"改为"**主账号名或店铺名任一行**"；注入页面的常量改为拼装自包含 helper（`pddBareAccount` / `pddAsciiLower` / `matchesAccount` / `matchesAccountFold`）。
- `electron/platforms/pdd-login.ts`：`identityProblem()` 分支重排（大小写店铺名 → 身份列表 → 账号大小写 → 掩码 → 账号不一致 → 兜底），报错文案能指出真正原因。
- `electron/platforms/pdd-adapter.ts`：诊断脚本的 `accountExact` 增加"剥姓名后比较"。

**验证**：`tests/pdd-login.test.cjs` 新增 5 条（真实姓名后缀、换子账号拒绝、保存值本身带姓名、无凭据复用、同主账号换子账号报不一致）；真机探针读真实 header 返回 `match:true`。

## 二、添加店铺的账号与店铺名录入

**现象**：新建店铺时店铺名只读、由账号冒号前那段推导，遇到"主账号名≠店名"必错；`主账号：子账号`（全角冒号）能重复入库；手机号主账号录不进去。

**改动**：
- 新增 `src/shop-account.ts`：`normalizePddAccount`（全角 ASCII 区转半角、去零宽字符、NBSP 转空格、剥尾部真实姓名、冒号两侧空白压缩）、`accountKind`（`main:sub` / `mobile` / `numeric-id` / `email` / `plain`）、`derivableShopName`（主账号不是普通名称时不给推导值）、`accountKey`（只折叠 ASCII 大小写）、`isMaskedAccount`。
- `src/domain.ts`：`resolveShopName(name, account, isNew, platform, derived?)` 改为**手填优先**，留空才用推导值；空值报「请填写与后台一致的店铺名称；登录账号可按「店铺名:子账号」填写」。
- `electron/shop-service.ts`：保存前归一化、掩码账号拒绝、去重与密码复用都按 `accountKey`。
- `src/components.tsx`：店铺名可手填并给出建议值（`nameTouched`），账号输入下方提示保存后的归一化写法与账号形态（子账号 / 主账号·手机号 / 数字 ID / 邮箱）。

**验证**：新增 `tests/shop-account.test.cjs`（9 条），`tests/core.test.cjs` 与 `tests/platforms.test.cjs` 按新语义更新。

- `src/ShopLogin.tsx` / `src/App.tsx`：核对成功后刷新店铺列表。
- `src/components.tsx`：店铺对话框显示「已绑定后台店铺 … · 账号 …」。

**验证**：`tests/pdd-login.test.cjs` 绑定相关 5 条 + `tests/shop-account.test.cjs` 1 条；真机探针返回 `{mallId: <后台店铺ID>, userId: <后台账号ID>}` 且 `matchBound:true`。

## 五、执行到「服务与承诺」报「当前API流程暂未支持发票类型设置」

**结论**：不是接口没接，而是**该类目根本不提供正品发票**——类目规则里 `authentic_invoice`、`is_electronic_invoice`、`is_paper_invoice`、`allow_invoice_sub_type`、`must_set_invoice` 全为 `false`，后台编辑页「服务与承诺」只有发货时间、7天无理由、假一赔十。

**改动**：新增 `apiInvoice(wants, rules)`，按类目能力裁决：
- 类目不提供发票 → 按不勾选执行，并在执行记录写明「当前类目的服务与承诺不提供正品发票」；
- 类目提供但 API 未支持 → 停止并提示「请在后台手动选择发票类型后继续」；
- 类目强制要发票而资料未勾选 → 停止并提示。

**验证**：`tests/pdd-api-draft.test.cjs` 新增 3 条。

## 六、批量导入（一份表 53 个 SKU）

**原状**：竖向模板一份表只出一件商品一个 SKU；图片顺序要求连续；公式一律拒绝；总量 80MB 上限；任一份坏整批失败。

**改动**：
- `electron/importer.ts`：
  - 公式先取缓存值（运营用 `拼单价/0.99` 算单买价），只有**无缓存值**的公式才报「请将公式转换成填写值后再导入」；
  - 金额统一四舍五入到整数（`money()`）；
  - 图片序号不再要求连续，只要求从 1 开始且不重复；
  - 同一张图**按内容去重**：`Map<hash, Promise<string>>` 在 `await` 之前登记，解决 53 行规格图并发写多份的问题；
  - 文件上限 400 → 600，总量上限 80MB → 1GB（单份表仍限 80MB）；
  - 逐份容错：返回 `{ products, assets, failures }`，失败逐份记录原因，不再整批失败；
  - 新增 `parseInstall()` 解析到店安装三项；`规格清单` 支持 `轮辋直径` 列。
- `electron/main.ts` / `electron/import-worker.ts` / `electron/preload.ts` / `src/types.ts`：`products:import` 返回 `{ products, failures }`。
- `src/App.tsx`：「选择文件夹」入口真正接通（删掉「待开发」弹窗与 `folderPending`），导入后提示坏表数量与第一份原因；无坏表时跑上架前体检。
- `src/TemplateDownload.tsx`：更新导入说明。

**验证**：用户给的 53 SKU 表解析为 1 件商品 / 53 SKU，资产 16 份（53 行规格图共用 1 张），端到端落盘 16 个文件；`tests/core.test.cjs` 新增「一份坏表不影响其余表导入」。

## 七、到店安装与轮辋直径

**需求**：轮胎类商品需要勾「到店安装」、选模板，并在「价格及库存」里给每行填**轮辋直径**（尺寸从商品名/规格取）。

```json
  "srv_template_id_map": { "2": "SIST_****" },
  "goods_srv_templates": [{ "type": 8, "id": "" }, { "type": 10, "id": "" }],
  "sku_srv_templates": "{\"rimDiameter\":\"17英寸\"}"
}
```

**改动**：
- 新增 `src/pdd-rim.ts`：从型号（`205/45R17`、`ZR18`、`20英寸`）推后台 27 个选项之一（13英寸及以下 / 14–20英寸 / 21英寸及以上，各带普通 / 防爆胎 / 雪地胎前缀）。
- `src/types.ts`：`InstallService`（`delivery: 'store' | 'home'`、`template`）、`Sku.rim`、`Product.install`、`Shop.installTemplate`、`apiDraft.installTemplateId`。
- `src/domain.ts`：开启安装时必须逐行有合法轮辋直径。
- `src/components.tsx`：`InstallEditor`（开启/关闭、类型、模板下拉、「读取后台模板」、「按规格自动填轮辋直径」、已填行数提示）；`src/ProductEditors.tsx`：规格表增加轮辋直径列。
- `electron/platforms/pdd-api-draft.ts`：`PDD_TEMPLATE_LOOKUP` / `PDD_TEMPLATE_OPTIONS`（在真实页面里把模板**名称**解析成 `SIST_` 编号，顺 React fiber 读 `memoizedProps.option`）；`apiInstallPair()` 只接受 `SIST_`；`apiRim()` 提交兜底。

## 九、库存为 0 被后台拦「请输入第 N 行规格的库存」

**根因**：后台「*库存」必填，`0` 在编辑页里就是一个空输入框，提交即被拦。

**取舍**：项目里「0 是真实库存」是有测试守着的语义（采集导出必须保真），不做静默改数。

**改动**：
- `electron/platforms/pdd-api-draft.ts`：**空值**按 1 件提交，显式 0 原样保留；
- `src/ProductEditors.tsx`：规格表上方新增提示条 + 「全部设为 1 件」一键补齐（只改空/0 的行）；
- `src/product-checks.ts`：体检文案改为「N 个规格库存为 0，上架时按 1 件提交，请在后台改成实际库存」。
