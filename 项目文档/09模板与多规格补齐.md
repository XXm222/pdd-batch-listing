# 模板与多规格补齐 0.1.3

日期：2026-09-30。按“去补齐”要求完成运营资料结构与桌面软件本机流程。

## 内容

- 商品资料保留四列纵向与黄色输入格，移除店铺、链接，价格库存移入规格清单。
- 新增规格清单，每 SKU 独立编码、至多两种规格类型、价格库存、可选规格图。
- 商品资料底部新增其他类目属性区；补齐 7 天无理由退货、发票和假一赔十服务。
- 泡脚桶示例为两 SKU，材质改为真实页面可选的塑料；所有数据为虚构测试资料。
- 读取器按表头读取三个页，保留旧两页兼容，支持图片文件夹匹配、规格图归档与 SQLite 保存。
- 识别弹窗可编辑 SKU、类目属性和售后承诺；检查重复 SKU 编码和组合、类型不一致、缺图、价格库存、材质选项及泡脚桶退货条件。
- 选店后展示待后台核验项，并将 pending 状态写入任务；执行记录显示这些项目。

## 依据与边界

当前泡脚桶材质选项、标题和图片要求、服务承诺来自本轮真实拼多多表单只读核查。品牌是否可用、其他类目规格类型、运费模板与履约承诺必须按所选店铺再次核验。当前规则是本机检查，尚未接入远端动态类目查询与自动登录。示例容量类型作为资料示例，未验证在后台可选，不宣称多 SKU 草稿已保存。

旧 Python 读取器改为按字段名匹配，支持由调用方传入所选店铺。旧执行器没有多规格和售后执行能力，v2 被明确拒绝，不会悄悄只写第一行 SKU。历史交付包未覆盖。

## 0.1.4 运营字段复核与修订

按用户要求，三位 agent 从 Excel 业务字段、导入校验和运营界面分别核查，再交叉讨论；主线程重新读取当前商家填写页、展开规格选项并复核 DOM，不以此前代码测试结果作为字段适配依据。

### 当前填写页确认

- 轮播图最多 10 张，比例 1:1 或 3:4、宽高大于 480px、3MB 内；这些条件不能套给详情图或规格图。
- 商品详情无必填星号，最多 50 张；页面明确未编辑详情时轮播图自动填入图文详情。
- 库存、拼单价、单买价必填。商家规格编码没有星号，作为选填；商品编码为软件管理编号。
- 品牌有星号且受店铺资质约束。材质标“重要”，适用人群和折叠属性未标必填；具体类目规则执行前核验。
- 参考价和满件折扣的星号位于 label 外，DOM 复核确认二者均必填。参考价提示大于商品最大单买价。折扣暂空只能进入待确认流程，不能推断后台无需配置。
- 当前类目必须支持七天无理由。规格类型列表确实包含容量；查看后已移除新增的空规格行，恢复原有 0/2 状态。该操作导致页面重建价格库存行，已还原库存 10、拼单价 39.9、单买价 49.9 及原规格编码，并再次读回确认。

### 修订

删除新运营模板的测试行、填写界面的测试控件、列表徽标和默认示例体验按钮。保留历史资料，系统不要求运营补该标识。三页和黄色纵向输入保留；填写要求区分软件必填、必填、建议、按类目、选店后确认和选填。规格编码改选填，建议属性不再因空值被强制拦截。轮播、详情、规格图分别处理，避免长详情图被错误拒绝。

品牌、运费和折扣可先留空，选店后再明确核验；待执行任务增加满件折扣及折后价格。状态改为“本机检查通过”，不表示平台已确认。普通现货实物商品资料是当前范围；商品资质、包装标签图、白底图和视频尚未纳入自动填写。

本轮未点击保存草稿或提交并上架，未写入商家后台。字段核查证据保存在 verification/0.1.4/；此前版本记录作为历史证据保留。

新版模板已同步到 resources/templates、运营资料和原工作目录 app-design-v3.1/templates；旧两页填写示例移到设计参考/历史资料，避免成为当前入口。Mac 0.1.4 实际窗口读取新空模板，确认没有测试控件，商品品牌、SKU选填、详情长图、运费/折扣待确认说明均可见；核对后取消，正常商品库保持 0 件，没有创建商品或任务。

## 真实在售商品核查：2026-09-30

### 结论

当前运营模板能承载并正确导入本次普通现货商品的基础资料。实际完成了“读取店铺商品 → 填入现有模板 → 选择文件夹导入 → 核对 → 保存本机资料 → 打开选择店铺”。本机保存的 25 项字段及图片顺序对照均无差异，35 张图片的文件内容、尺寸与下载资源一致。

流程方向合理，店铺在商品资料保存后选择可以保留。但当前 App 尚不能作为完整的自动上架或后台草稿软件交付：自动登录、切店、远端规则核验、后台填写、草稿保存和结果回读均尚未接入。本轮没有点击后台保存草稿、提交、上架或下架按钮。

### 合理的最终操作顺序

运营提供一份商品 Excel 及同级 images → 自动匹配并弹出结果 → 核对标题、类目、属性、SKU 价格库存、图片及交付承诺 → 保存本机资料 → 选择或添加店铺 → 软件登录并确认实际店铺身份 → 核验目标类目、品牌、运费、规格选项及平台承诺，集中提示需要补充的项目 → 自动填写并保存后台草稿 → 回读草稿 ID、SKU 数量、价格和图片数量 → 执行记录显示实际结果。

“选择店铺”之后必须有店铺规则核验和真实执行。新建草稿与更新已有后台商品需要不同的明确动作；本次取现有商品资料核查，不表示软件已经支持修改该商品。

## 单 Excel 交付更新：0.1.5，2026-09-30

### 运营填写与导入方式

根据用户要求，主流程改为一个 `.xlsx` 包含商品资料、规格清单和全部图片。模板版本为 3，图片清单预留连续的 10 张轮播图、50 张详情图，图片用途和顺序保留，原文件名栏改为图片栏。多规格图插在对应 SKU 行的“规格图”列。运营无需额外图片文件夹或图片命名，只需上传 Excel、确认识别结果、保存本机资料，再选择店铺。
