## 主页与执行记录

主页进度弹窗承接正在执行或需要继续处理的本次任务：

1. 开始执行后自动打开“商品执行进度”；左侧按本次队列显示商品，右侧显示当前件、目标店铺、当前阶段与本次耗时。
2. 展示已确认保存件数与本次总件数。保存结果不确定或被中断的商品仍待核对，不能计入已保存。
3. 展示 12 个步骤及各步最新尝试的状态、耗时。阶段、异常与保存结果来自任务事件和任务数据。
4. 当前件完成后跟随后续正在执行的商品；暂停或失败时保留需要处理的商品。
5. 支持收起/关闭和主页“查看执行进度”重开。运行中的任务收起后继续执行；“暂停执行”须等当前操作退出后停止。
6. 继续执行、检查浏览器连接、编辑或更新商品资料、核对店铺、重新填写与 Agent 诊断按任务状态提供。尝试过保存时先核对原草稿；恢复后只接续当前未完成商品和同店铺的后续待执行商品。

| 顺序 | 执行步骤 |
| --- | --- |
| 1 | 连接浏览器 |
| 2 | 登录并核对店铺 |
| 3 | 检查商品图片 |
| 4 | 打开商品填写页 |
| 5 | 填写基本资料 |
| 6 | 填写规格、价格和库存 |
| 7 | 设置发货和售后 |
| 8 | 上传商品图片 |
| 9 | 核对填写结果 |
| 10 | 保存后台草稿 |
| 11 | 核对已保存资料 |
| 12 | 确认草稿箱结果 |

执行记录仅展示已完成或已停止的结果；排队、执行中和 Agent 正在处理的任务不进入历史列表。保留历史结果、失败原因、分步耗时、日志、核验及清理/恢复，通过“在主页打开任务”进入对应进度弹窗处理。新执行使用当前商品资料与所选店铺，不继承旧历史的商品编号和保存状态；活跃任务与队列仍受互斥及清理保护。清理只收起本机记录，恢复保留原历史证据。

## 规格确认补强

原生输入后先发送 Tab，再核对原控件是否失焦。如果原控件仍保持焦点，且页面、输入事务标识与输入值仍一致，才对该原控件调用 blur 并确认焦点离开。已失焦时不重复 blur；不重新输入文字，不聚焦替换控件，不发送 Enter。控件拒绝失焦或事务/value 不一致时停止。

规格选项按实际值确认，不依赖后台选项排序。异值、重复值、维度或完整组合表不一致仍停止；完整组合表验证保留，只有核对全部组合后才填写对应价格和库存。六组合的价格映射已有回归覆盖。

失败日志记录实际观察到的规格值、控件和组合情况。新失败说明使用“输入后未确认”等可证实措辞，不把本机超时推断为平台拒绝商品。旧任务历史保持原错误信息，当前 UI 截图里的旧失败原因不等于 0.1.36 已重新执行得到的结论。
