# 运行时 Agent 接入 0.1.12

更新日期：2026-10-04。用户已确认采用云端 OpenAI 兼容接口。

## 已实现

- 左侧底部“Agent 模型设置”：接口地址、模型、API Key、密钥隐藏、删除已存 Key、保存及连接验证。
- 停止的异常任务“Agent 诊断”：发送范围、可选只读原填写页、模型调用、建议依据、确认动作与诊断来源耗时。
- 主进程 `AgentService` + `ModelClient`，使用原生 fetch，无新增模型 SDK 或 LangGraph 依赖。
- 模型最多三轮请求、两个白名单只读工具。禁止模型任意 JavaScript、账号操作或业务自动修改。
- 已保存诊断记录当时模型与接口，新诊断单独显示当前配置。修改读取范围须重新诊断；选择建议后仍可重新诊断。
- 建议确认时复核任务指纹。已尝试保存只能回查原草稿或人工核对。标准填表不请求模型。
- Key 单独存入 SQLite settings 的密文列；配置 IPC 仅返回 keySaved。更换接收地址不沿用旧 Key。

## 使用

1. 打开 Agent 模型设置，填写服务商的 Base URL、支持工具调用的模型 ID 和 API Key。
2. 点“验证连接”，确认模型有回答；点“保存设置”。验证当前输入不会隐式保存。
3. 任务停止并出现异常时，点“Agent 诊断”，核对接收接口与发送字段范围，按需勾选读取原后台填写页，再开始诊断。
4. 阅读建议与来源。编辑建议由运营手工核对并保存；继续或回查建议经确认后交给原任务脚本执行。

Key 直接在 App 填写，不必发在聊天。供应商的使用费用按其账户计费。当前没有默认云端模型、默认密钥或借用 Codex 登录凭据。

## 当前验证

源码 TypeScript / Vite 构建通过。`verification/0.1.12/Agent协议与边界核查.json` 记录 14 项本机核查，包括真实本机 HTTP 请求、工具循环、拒绝任意工具、无页面授权不捕获、旧建议失效、保存不明限制、重启恢复、API Key 不进入普通返回值/诊断结果与错误正文过滤。

这些核查使用明确的本机协议 fixture 及注入加密函数，不是云端模型或新 Key 的操作系统凭据验收。桌面核查也使用独立资料库，响应和商品任务明确标为“界面核查（未执行后台）”；不向真实店铺写商品。截图位于 `.impeccable/review/`，收尾记录见对应 brief。
