# 默认浏览器草稿执行 0.1.8

日期：2026-10-04。授权范围：仅保存后台草稿。

## 运营操作

上传 Excel → 核对识别结果并保存 → 勾选商品 → 选择保存的店铺 → 开始填写并保存草稿 → 执行记录回显。

沿用系统默认浏览器用户资料。本机默认浏览器是 Chrome，Kimi 扩展已连接本机桥接服务。登录店铺和子账号一致时复用登录；不一致时退出并使用本机加密账号密码登录。验证码由运营完成后继续。Excel 不填店铺与后台链接。

## 当前后台页面取证及实现

- 选类目依次点击完整路径的 `li.content-cat a.cate`，再点击“确认发布该类商品”进入填写页；此按钮本身不发布。
- 未保存的 add 地址重开会丢失类目上下文。保存前重试重新选类目；已尝试保存后仅回查原商品编号。
- 品牌和类目属性取当前下拉可用选项；无匹配项停止提示，不编造后台属性。
- 单规格无买家选择可留空两组名称和值；后台多规格按类型和值生成组合，规格值失焦才生成 SKU。
- 后台产生完整规格组合，Excel 缺组合会停止；需预览图的组合未给图时停止。
- 轮播图和详情图分别批量上传，Excel 原始顺序传入；图片计数包含上传中的文件，必须等远端图片地址齐全后保存。
- 轮播图满 10 张后上传控件消失；数量读自图片区域而不是上传控件。
- 保存结果不明保留 goodsId；继续只核对此编号，不再新增。
- 草稿箱“编辑”打开 type=edit 地址；不能用初次 add 地址回读。编辑页满件折扣是“满2件 9.9 折”文字，需要兼容文字和输入框。
- 执行记录显示步骤、本次执行耗时、商品编号、后台状态和截图；进后台后 App 继续刷新进度。

## 交付与依赖

Mac arm64 包为 Electron 桌面应用，运行不需 Node/Python；需要默认 Chromium 浏览器装 Kimi 扩展并连接本机桥接。当前执行器使用 Kimi 的本机 HTTP 命令，密码不返回渲染界面和日志。桥接地址由已安装服务 start 输出读取，缺少服务或扩展连接时明确提示。

Windows x64 配置仍在项目中，未交付经过真机运行的 Windows 包。Mac 包尚未完成 Developer ID 签名、公证与他机安装验收。
