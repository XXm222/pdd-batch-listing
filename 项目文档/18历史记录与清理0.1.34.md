# 0.1.34 历史记录与清理

## 操作

- 重新执行：在商品资料勾选商品，再选择店铺。待执行、失败、等待处理、保存结果待核对、已保存及已清理的历史记录均不拦截新任务。
- 继续原任务：在执行记录使用原任务入口，保留原商品编号和保存状态；已尝试保存的任务先读回原草稿。
- 清理一条：点击记录右侧“清理记录”。
- 清理多条：勾选记录，再点“清理所选”。也可点“清理全部”。
- 恢复：切换到“已清理”，使用“恢复记录”“恢复所选”或“恢复全部”。

每次新执行单独产生任务。清理不会删除商品资料、店铺、图片、保存证据或后台草稿。当前任务执行或 Agent 诊断期间先等待结束或暂停，避免清理仍在运行的队列。

## 实现

- 历史拦截改为仅检查正在执行的任务与正在诊断的 Agent；主进程继续保护正在占用浏览器的队列。
- 清理在本机事务中设置 clearedAt，恢复设为 null，修订号递增并向界面发送更新。
- 已清理任务不参与批量继续，不能直接恢复运行或诊断；先恢复显示后才可继续原任务。
- 批量选择包含无效或活跃任务时整批拒绝，避免部分清理。
- 新建任务与继续原任务的保存读回策略独立，未修改自动保存或发布逻辑。

## 验证边界

编译与相关本机回归检查通过；真实拼多多后台新建流程因浏览器操作工具的 URL 限制尚未重验。Mac 安装包的清理与恢复结果见同版本 verification 记录。
