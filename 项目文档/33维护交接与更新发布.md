# 维护交接与更新发布

当前版本0.1.63，更新日期2026-10-09。接手者从 [GitHub仓库](https://github.com/XXm222/pdd-batch-listing) 拉取main，在自己的电脑开发维护。操作、代码和本版验收说明分别见 [README](../README.md)、[架构](02技术选型与架构.md)、[发布与验证摘要](35发布与验证0.1.63.md)。

## 获取源码与开发环境

使用Node.js 24.19.0、pnpm 11.19.0及Git，依赖版本与package.json、pnpm-lock.yaml保持一致。

```sh
git clone https://github.com/XXm222/pdd-batch-listing.git
cd pdd-batch-listing
git switch main
pnpm install --frozen-lockfile
node node_modules/electron/install.js
pnpm dev
```

`pnpm dev`同时运行Vite与Electron。需要隔离测试时，在启动进程前设置`GOODS_WORKSPACE_DATA_DIR`为测试目录；正常业务资料位于系统应用数据目录，开发验收不得删除原业务数据。

0.1.63新建拼多多任务默认API草稿流程，无需环境变量；任务的`executionMode`持久化，原有任务继续原流程，恢复不会切换写入方式。API复用已登录浏览器的正常客户端，不保存Cookie或校验值；普通单选属性、新建草稿与24/48小时发货已接入，复杂模板、发票类型及其他店铺/类目的验收边界见[API记录](34接口草稿提交验证.md)。Mac试用资料库单独保留，正式版继续使用原本机资料库。

## 更新签名配置

服务器登录权限与更新签名是两项独立配置。向项目负责人安全领取与现有客户端公钥匹配的Ed25519私钥，配置为：

- 默认：`~/.config/goods-workspace-updates/release-private.pem`。
- 自定义：环境变量`GOODS_UPDATE_SIGNING_KEY`指向私钥文件。
- 对应客户端公钥：仓库`resources/updates/release-public.pem`。

不能为了让发布脚本通过就重新生成密钥替换现有公钥，否则已安装客户端无法验证新版更新。私钥、SSH密钥、密码和Token不提交Git，也不放进公开更新目录。发布脚本会检查私钥与现有公钥是否匹配。

## 一次完整版本发布

1. 拉取并核对当前main，完成修改；更新`package.json`的`version`与`build.directories.output`、`resources/release-notes.txt`以及README和相关文档。版本目录采用新的稳定版本号，已发布目录不覆盖。
   README需同时检查顶部版本、横幅版本、下载状态、操作说明、本版更新、验证范围与文档导航，不能只更新底部发布段落。
2. 完成格式、类型、测试与构建检查；界面变化需检查当前界面，业务填写变化需按授权范围核验目标店铺真实页面与读回。
3. 生成Mac arm64 DMG与Windows x64 NSIS。Mac包在Apple Silicon Mac上构建；当前工作流能在Mac生成Windows安装包，这不代替Windows实机安装验收。

```sh
pnpm format:check
pnpm typecheck
pnpm test
pnpm build
pnpm exec electron-builder --mac dmg --arm64
pnpm exec electron-builder --win nsis --x64
pnpm updates:publish
```

脚本先核对两平台包与当前构建、模板、WASM及Worker，生成文件大小和SHA256，签名`latest.json`；然后上传服务器、核对远端SHA256，最后切换下载链接与清单。平台包不齐、密钥不匹配、目标版本已存在时停止，不强行绕过。

4. 重新读取公开`latest.json`，核对版本、签名和两个平台下载地址及大小；在旧版App左下角“软件更新”确认能检查新版，下载校验后打开安装包升级。Mac拖入原位置替换，Windows使用原安装目录。运行中的任务需先结束，升级后检查资料保留。
5. 将本次明确修改的源码和文档提交并推送GitHub；确认macOS与Windows CI结果。数据库、用户商品和图片、浏览器缓存、密钥、安装包构建目录不提交Git。
6. **另外创建GitHub Release**：标签为`v版本号`，指向本次核验源码提交；上传两个安装包、`SHA256SUMS.txt`、`LICENSE`与`NOTICE`，填写变化及实际验证边界。可以先创建草稿，核对上传资产大小和SHA256后再发布为Latest。

Git推送不会自动更新GitHub Release，GitHub Release也不会自动更新`www.mandla.cn`渠道。三处分别核对：main源码及文档、Release标签及资产、服务器版本清单及下载链接。

## 只修改文档时

校对版本、功能说明、路径及链接后单独提交、推送main；相关Release说明可链接最新维护文档。不提升软件版本、不重打已发布安装包，也不移动已发布标签。安装包对应源码提交与当前维护文档版本在发布摘要中分别记录。

## 保持证据边界

本机检查、CI、包内一致性、界面测试桩、原生安装、真实后台填写、保存读回和正式发布分别记录。历史成功不能当成本版重验结果。当前仅开放拼多多草稿；淘宝关闭，京东未接入。正式发布、资质审核及未验证店铺/类目不自动推定完成。
